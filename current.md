Implementation summary
RuntimeContextPaths (lexicon-core/src/session/context.rs) gained a validated source_state_directory: Option<PathBuf> field: Some(operation_root/state) for Acquisition, None for Processing, with disagreement (wrong path, present-when-should-be-absent, or absent-when-should-be-present) rejected via a new RuntimeContextError::SourceStateDirectoryDisagreement variant, following the same validation style as operation_root/raw_data_directory/processed_data_directory. The field round-trips through the LEXICON_RUNTIME_CONTEXT_V1 document (encode_runtime_context / decode_runtime_context) using the existing per-platform native-path encoding; it is omitted entirely from the wire document for processing invocations via #[serde(default, skip_serializing_if = "Option::is_none")].
All three RuntimeContextPaths::new call sites were updated to supply/derive the field: decode_runtime_context (lexicon-core/src/session/context.rs) decodes it from the document; build_session_paths (lexicon-framework/src/session/coordinator.rs) derives it from the operation being launched; RuntimeInvocationFixture::new (lexicon-core/src/session/test_support.rs) derives it the same way for tests.
SessionDataPaths gained an equivalent optional field and accessor. HttpAcquisitionContext (lexicon-core/src/protocols/http/context.rs) gained source_state_directory() -> Option<&Path> and a new ensure_source_state_directory_ready() method that creates the directory (if absent) and validates it via the existing validate_managed_path machinery; run_http_runtime_invocation (lexicon-core/src/protocols/http/runner.rs) calls this immediately after constructing the context and before invoking the acquire/resume handler, per specs.md's "Core must create and validate the directory before calling source code" requirement. A new HttpRuntimeInvocationExecutionError::SourceStateDirectoryPreparation variant reports failures at this step. Processing contexts are unaffected: they have no source-state directory and no corresponding creation step.
New tests (11 total)
* 8 unit tests in lexicon-core/src/session/context.rs (source_state_directory_tests module): acquisition path derivation, processing absence, rejection of a disagreeing acquisition path, rejection of a missing acquisition path, rejection of a present processing path, rejection of path traversal in the field, encode/decode round-trip for acquisition (Some, and confirms the field is present), encode/decode round-trip for processing (confirms the field is entirely absent from the JSON and decodes back to None), and SessionDataPaths preserving the field from RuntimeContextPaths.
* 2 fixture-backed tests in lexicon-core/src/protocols/http/runner.rs execution_tests (Tests 20-21): source_state_directory_is_created_and_writable_before_handler_runs (proves Core creates the directory before the handler runs and that it is writable) and source_state_directory_persists_across_sequential_sessions (proves a marker file written by one fixture-driven session's handler is still present and readable by a second, independently-prepared session against the same operation root, via a new RuntimeInvocationFixture::advance_to_new_session() test-support method).
